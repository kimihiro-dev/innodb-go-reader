# 项目约定

## 状态来源与范围

- 每次会话先读 REQUIREMENTS、DECISIONS、TODO 和本文件。当前详细兼容性统一链接[支持矩阵](format/83-release-support-matrix.md)。
- 需求与已采纳决议冲突时明确指出并澄清；不要以历史「尚未支持」覆盖当前范围，也不把候选计划当成已批准功能。
- 文档归属见[导航职责表](README.md)。源码标签 v0.1.0 不移动，版本与发布选择见 [D009](DECISIONS.md#d009v010固定既有源码文档独立演进)。

## 工程约定

- Go 1.25 或更高，模块 `innodb-go-reader`，根包 `innodb`；当前只使用标准库，Go 修改使用 gofmt。
- 参考目录和 MySQL 官方源码只读核查，不随本项目修改。
- 做与请求直接相关的最小修改。实现前记录问题、备选与验收；新决议在实施前追加，任务开始/完成时同步 TODO。
- `io.ReaderAt` 和文件大小为读取输入，调用方保证快照/schema 稳定并负责打开/关闭。gzip 解压由调用方处理，不混入物理解析。
- 错误用 `%w` 包装并保留上下文；通过 `errors.Is` 区分损坏、不支持、预算、停止以及底层 I/O/context 错误。
- SQL NULL、空文本、空二进制和未物化列保持区别；整数/精确小数不经 float64 中转，文本保留源字节，空间坐标保持存储顺序。
- Read 系列失败不返回部分结果；流式入口的已交付前缀不可撤回，必须检查 error 与 Complete。取消不能保证打断任意阻塞 I/O/回调，预算不承诺 RSS。
- Record 的 Start/Offset/End 是页内位置；Result.Page 是根页，Pages 是聚簇 DFS 访问顺序，LOB 来源由 External/Chunks 表达。不同索引/分区来源不混成用户列。
- VIRTUAL 只在显式物化入口中单独报告，不求值或填伪 NULL；二级物理项/投影使用独立模型，不伪装完整表行。

完整的类型、键、DDL/DML、LOB 和协议细节见第 83 章及其章节链接，本文件不再逐阶段重复声明支持限制。

## 验证与证据

- 固定夹具离线验证，原始文件通过 SHA256 核对；损坏实验只修改副本。较大夹具用 gzip 无损保存，SHA 对解压后的物理文件计算。
- 新物理样本记录生成 SQL、版本、配置、采集过程与独立预期；只使用专用库/会话，不修改既有表或保存密码。
- 真实 SQL/官方工具预期、合成损坏测试、Go 派生结果各自标明性质。相同数据来源的两个 Go 输出不称为独立预期。
- CRC 损坏测试不重封装校验和；需要进入结构校验的副本可以重封装，并明确标为合成输入。
- 日志保留实际执行环境、缓存状态和最终结果。历史通过不写成本轮执行，主动 fuzz 次数不累计不同运行；浏览器反馈与自动验收分开记录。
- 源码变更运行适用测试；完整复验见[第 84 章](format/84-release-validation.md)。纯文档整理验证内容与引用，不无意义地重复长回归。
- 扩展版本、页大小、类型、布局或协议时同步更新矩阵、决议、独立预期与复验记录；已有类型测试不能推定新组合成功。
- `docs/release-validation` 原始报告/日志与 `testdata` 独立证据不做文风重写。阶段验证数字只在 HISTORY 或原始证据中维护。

## 文档维护

### 文件职责

按[文档导航职责表](README.md)选择唯一正文位置，其他文档用摘要和链接引用。合并相似记录时保留独有理由、数字、异常和边界；同一组验收结果集中记录一次。

### 解析手册

- 每个实现步骤同步交付中文解析文档；章节包含学习目标、前置概念、结构图、字段偏移/长度/字节序/含义、真实夹具字节、逐步解码、代码入口、验证与边界。
- 明确区分文件绝对偏移、页内偏移与记录相对偏移；整数编码、字符字节数和 NULL 等易混概念通过例子解释。
- 使用贯穿案例串联章节，目录标明当前支持与历史范围；格式解释应让读者无需先读 Java 参考实现就能理解 Go 实现。

### 统一格式

- 每份 Markdown 只有一个一级标题，层级连续；章内小节不混用「1.」「一、」和无编号样式。手册一级标题固定为 `# NN. 标题`。
- 文件名、阶段 `stage-N` 和发布版本锚点保持稳定。改标题时检查所有入链并保留旧锚点别名，不能依赖改完后的自动生成 ID。
- 标题、顶层列表、表格、代码块与相邻正文之间留空行；连续空行只留一行。使用 UTF-8、LF 和文件末尾换行。
- 日期写 `YYYY-MM-DD`，未知日期写「未记录」；任务状态只用「待办 / 进行中 / 已完成 / 待外部条件」。历史提案标明编制日期和历史性质，不显示为当前待审批事项。
- 当前决议使用「编号、日期、状态、问题、决定、备选、依据」。新决议不复用编号；替代时明确旧编号和理由。
- 类型、API、字段、参数与路径用行内代码；源码引用使用可点击路径和有效行号。代码块注明语言，真实十六进制/偏移/输出从固定夹具提取，示意内容明确标记。
- 不对代码块、数据表、原始字节、SQL、预期输出做批量文字替换。教学中的同一例子可以重复引用，但验收日志不能在状态文件多份复制。

### 每次修改的检查

1. 确定内容唯一归属，先补决议和任务状态，再修改对应正文；别在四份状态文件同时粘贴一段结果。
2. 更新受影响的目录和交叉引用；保持手册文件名与版本标签。历史唯一理由/证据必须可追溯，删除重复内容时保留正文链接。
3. 在仓库根目录运行 `python3 scripts/check_docs.py`，检查标题、代码围栏、本地文件/锚点和源码行号；该检查器不联网或修改文件。
4. 阅读 diff，检查代码块/字节/表格、事实边界与状态；涉及归档或移动还要核对相对链接。通过检查后更新 TODO，结果记录在唯一证据位置。

文档检查器只覆盖结构和引用，不能证明字节/SQL或支持承诺正确；内容必须对照源码、当前矩阵与独立证据。维护分工的决议见 [D010](DECISIONS.md#d010文档分工与唯一正文)。
