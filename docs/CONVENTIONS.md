# 项目约定

## 状态来源与范围

- 每次会话先读[需求](REQUIREMENTS.md)、[当前任务](TODO.md)和本文件；详细兼容性以[支持矩阵](format/83-release-support-matrix.md)为准。
- 以当前源码和文档理解项目，不维护发展路径、编号决议、施工计划、已完成任务流水或历史档案。新需求的当前契约直接更新需求和技术正文。
- 请求与当前范围冲突时指出差异；用户明确变更范围时按新指示更新，否则先澄清。候选不等于已批准实现，未验收版本/组合不得推定支持。
- 当前源码、开发和构建以当前分支最新提交（`HEAD`）为准，不锁定版本标签或指定SHA；已有标签仅表示历史发布。构建时记录实际提交，见[构建指引](RELEASING.md)。

## 工程约定

- Go 1.25或更高，模块`innodb-go-reader`，根包`innodb`；物理解析使用标准库，Schema采集使用go.mod锁定的Go MySQL驱动，其他依赖不得自行扩大。Go修改使用gofmt。
- 做与请求直接相关的最小修改，避免无关重构。实现前在当前需求中明确问题、选定方案和验收；未解决的问题先澄清，当前任务同步开始/完成。
- 优先复用标准库、已有依赖和既有解析路径，不为单次使用建立通用框架；不逐类移植参考项目。
- 参考目录及MySQL官方源码只读核查；产品Schema命令仅采元数据，稳定物理快照由外部备份工具提供。
- 输入为`io.ReaderAt`及文件大小，调用方保证快照/schema稳定并负责打开/关闭；gzip解压由调用方处理，不混入物理解析。
- 错误用`%w`包装并保留上下文，通过`errors.Is`区分损坏、不支持、预算、停止和底层I/O/context错误。
- SQL NULL、空文本、空二进制和未物化列保持区别；整数/精确小数不经float64中转，文本保留源字节，空间坐标保持存储顺序。
- Read系列失败不返回部分结果；流式前缀不可撤回，须检查error与Complete。取消不保证打断任意阻塞I/O/回调，预算不承诺RSS。
- `Record.Start/Offset/End`为页内位置；Result的根页、DFS页序、导航与External/Chunks来源分别保留，不同索引/分区不混成用户列。
- VIRTUAL只在显式仅物化入口单独报告，不求值或填伪NULL；二级物理项/投影采用独立模型，不伪装完整表行。
- Git配置只在当前仓库设置，凭据和缓存不提交；正常推送，不强制覆盖历史，GitHub Release由用户手动创建。
- stdout写数据，stderr写诊断；文件完整成功后原子发布，默认不覆盖，并保护输入及可识别别名。发布或外部写入按用户授权范围执行。

## 验证与技术证据

- 固定夹具离线验证，原始文件用SHA256核对；损坏实验只改副本。较大夹具用gzip无损保存，SHA对解压后的物理文件计算。
- 新物理样本保存准确版本/配置、生成SQL、采集过程和独立预期；只使用专用库/会话，不修改既有表或保存密码。
- 源码事实、真实SQL/官方预期、合成损坏测试和Go派生结果分别标明；两个Go输出互比不称独立预期。
- CRC损坏测试不重封校验和；为进入结构校验而重封的副本须明确标为合成输入。
- 源码变更运行适用回归；环境、缓存、失败与最终结果如实保存。已有通过不当作本次执行，交叉编译不等于目标平台运行认证。
- `docs/*-validation`中的原始报告/日志/数据及`testdata`保留为验证依据；导航见[验证资料](README.md#验证资料)。仅修正文档链接，不将其改写成当前支持承诺。
- 纯文档修改检查内容、链接、diff和受影响资产，不重复长解析回归；完整复验入口见[第84章](format/84-release-validation.md)。

## 文档维护

### 文件职责

- REQUIREMENTS维护当前范围/验收，TODO只列正在进行及明确待办事项，完成后删除任务项；CONVENTIONS维护实施规则，不追加施工日记。
- 支持矩阵集中兼容性和API契约，CLI指南维护可复制操作示例，解析手册维护物理解释和验证方法；文档目录负责导航和资料索引。
- 同一内容保留唯一正文，其他位置用摘要和链接。新功能/版本/协议同步相关正文，不再创建决议、历史或阶段记录。
- 构建文档默认跟随最新提交；版本发布说明只描述对应标签的历史内容，后续开发依据当前需求和矩阵。

### 解析手册

- 章节包含学习目标、前置概念、结构图、偏移/长度/字节序/含义、真实字节、逐步解码、代码入口、验证与边界。
- 区分文件偏移、页内偏移与记录相对偏移；用实际样本说明整数、字符长度、NULL等易混概念，源码事实和样本观察分别标明。
- 系统表空间等知识说明不等于已实现解析；当前支持以矩阵为准，不从教学例子外推其他版本或组合。

### 统一格式与检查

- 每份Markdown只有一个一级标题，层级连续；手册一级标题为`# NN. 标题`，小节不混用编号风格。
- 标题、列表、表格、代码块与正文间留空行；使用UTF-8、LF及末尾换行，不连续堆叠空行。
- 文件名与有效技术锚点保持稳定；改标题/移动/删除文档时同步修复引用，不留指向已清除记录的链接或编号。
- 类型、API、字段、参数和路径用行内代码，代码块注明语言；真实输出和字节来自固定样本，算法示意明确标记，不批量改写数据/SQL/代码块。
- 修改后运行`python3 scripts/check_docs.py`并阅读diff；根据修改范围核对实现、独立预期及文件指纹。检查器不替代内容正确性验证。
