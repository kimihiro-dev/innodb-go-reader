# 项目需求

## 问题与目标

用 Go 离线读取受支持的 MySQL InnoDB 物理文件，完整还原当前存储列值，并提供可复核的中文解析手册和命令行工具。

已确认的数据还原优先原则：不将不支持的数据静默省略、填零或替换为 SQL NULL。每项解析能力必须同时交付格式解释和独立验证；不做 Java 参考项目的逐类移植。

## 输入与支持范围

详细类型、键、布局、API 与预算以 [第 83 章支持矩阵](format/83-release-support-matrix.md)为唯一正文。本文件只列判断输入所需的概要：

| 维度 | 已确认范围 |
|---|---|
| 数据来源 | MySQL 8.0.45、16 KiB、独立非压缩非加密表空间；目标写事务已结束且整个读取期间稳定的快照 |
| 行格式 | DYNAMIC、COMPACT；已验收的 UPDATE/DELETE、当前 LOB、原生 INSTANT ADD/DROP |
| 列值 | 已支持的数值、文本/二进制、日期时间、ENUM/SET、JSON、二维空间值及 SQL NULL |
| 文本 | utf8mb4、utf8mb3、ascii、MySQL latin1；字符键限已验收的四个 `_bin` 规则 |
| 索引 | 多层聚簇树、复合/ASC/DESC 键、唯一非空聚簇键与隐藏 DB_ROW_ID；受支持普通 BTREE 二级树 |
| 元数据 | 支持 SDI 提取、自动发现和可信显式 schema；不保证识别所有错误外部 schema |
| 生成列 | STORED/INVISIBLE 物化值；VIRTUAL 仅通过显式物化视图单独报告，不求值或填伪 NULL |
| 分区 | 完整普通 RANGE/LIST/HASH/KEY 独立文件集合，定义序扫描并保留来源 |
| 工具 | metadata、page、export、query、check、space、visualize；JSONL/CSV 带类型无损协议 |

「支持」不意味着这些维度的任意组合均经过实测。完整类型物化单值上限为 16 MiB；其他容量和资源限制不在此重复，见支持矩阵。

## 验收标准

1. 受支持输入的全部请求列值与独立 SQL/官方工具预期一致，精度、类型、NULL 与空值保持区别。
2. 物理偏移、记录/树/LOB 来源与固定夹具可逐字节复核；原始资产不改写。
3. 可检测损坏、不支持或超限明确报错；完整结果不返回部分成功，流式输出检查最终状态。
4. 当前范围、非目标、失败和预算契约在文档中可查；格式解释、使用示例及对应验证随能力一起交付。
5. 实现变更运行适用回归；完整首版复验与独立证据入口见 [第 84 章](format/84-release-validation.md)。历史缓存结果不得表述为本轮重新执行。

## 明确非目标

- 不承诺其他 MySQL/MariaDB 版本、其他页大小、系统/通用表空间、压缩或加密兼容。
- 不实现在线快照采集、redo/undo 回放、MVCC 可见性、事务恢复或删除历史值还原。
- 不实现通用 SQL/生成表达式/空间拓扑引擎，或 FULLTEXT/SPATIAL/函数/多值索引。
- 不提供子分区、集合范围查询、分区路由和跨分区全局键归并。
- 不因版本标签增加永久 API 兼容承诺；发布仍按用户授权范围执行。
