# 02 从文件到数据页

学习目标：用页号定位文件字节，解释 FIL/INDEX 头，验证找到的是正确的单叶子页。前置知识：[第 01 章](01-table-to-file.md)。

## 1. 三种偏移不要混淆

页大小固定为 16384 字节。页号从 0 开始：

```text
文件偏移 = 页号 × 16384 + 页内偏移
第 4 页起点 = 4 × 16384 = 65536 = 0x10000
该页偏移 155 的字节 → 文件偏移 65691 = 0x1009b
```

`page.go/readPage` 使用 `io.ReaderAt` 定位读取，不通过扫描文本或寻找某个数值猜测页位置。读取前检查文件长度是否按页对齐、请求页是否在范围内；读取后检查实际读取长度和 FIL 页号。

## 2. 单个 INDEX 页的分区

```text
页内偏移
    0 ┌────────────────────────────┐
      │ FIL header          38 B   │
   38 ├────────────────────────────┤
      │ INDEX header        36 B   │
   74 │ 两个 FSEG header     20 B   │
   94 ├────────────────────────────┤
      │ infimum / supremum  26 B   │
  120 ├────────────────────────────┤
      │ 用户记录堆（含记录元信息） │
  239 ├──── 本样本 heap_top ────────┤
      │ 中间空闲区域               │
16372 ├────────────────────────────┤
      │ 页目录，本样本 2 × 2 B     │
16376 ├────────────────────────────┤
      │ FIL trailer          8 B   │
16384 └────────────────────────────┘
```

239 是样本值，不是格式常量。记录从前部使用空间，页目录从尾部向前占用空间；程序检查两者不能重叠。

## 3. FIL header：所有页的公共身份信息

下面多字节数均按大端解释；“保留”不代表已实现相应业务。

| 页内偏移 | 字节数 | 字段 | 主案例第 4 页 |
|---:|---:|---|---|
| 0 | 4 | 页校验和字段 | `bc f5 b4 04`，本步暴露而不校验 |
| 4 | 4 | 页号 | `00 00 00 04` → 4 |
| 8 | 4 | 前页号 | `ff ff ff ff` → 无前页 |
| 12 | 4 | 后页号 | `ff ff ff ff` → 无后页 |
| 16 | 8 | 页 LSN | `00 00 00 00 1c a9 6f e4` |
| 24 | 2 | 页类型 | `45 bf` → 17855，INDEX |
| 26 | 8 | 版本/用途相关保留区 | 本步不解释 |
| 34 | 4 | space ID | `00 00 00 28` → 40 |

LSN 是日志位置相关信息，不是 SQL 行号或时间戳。前后页字段与索引层上的页链接有关；我们要求根页是唯一叶子，所以本阶段必须没有前后兄弟页。

页尾 `[16376,16384)` 原始值为 `bc f5 b4 04 1c a9 6f e4`。最后四字节在此样本与头部 LSN 的低 32 位一致；前四字节涉及校验机制。程序保留 8 字节，不把这种相等检查宣称为完整 CRC 验证。

## 4. INDEX header：这个页如何组织记录

相对于页起点，关键字段如下：

| 偏移 | 长度 | 含义 | 当前样本 |
|---:|---:|---|---|
| 38 | 2 | 目录槽数 | `00 02` → 2 |
| 40 | 2 | heap_top，堆末尾后一字节 | `00 ef` → 239 |
| 42 | 2 | compact 标志 + 堆记录数 | `80 06` → 新式格式，6 条堆记录 |
| 44 | 2 | free 记录链入口 | 0 |
| 46 | 2 | garbage 字节数 | 0 |
| 48 | 2 | 上次插入记录位置 | `00 de` → 222 |
| 50 | 2 | 插入方向 | 本步不依赖 |
| 52 | 2 | 方向计数 | 本步不依赖 |
| 54 | 2 | 用户记录数 | `00 04` → 4 |
| 56 | 8 | PAGE_MAX_TRX_ID 区域 | 本步不使用 |
| 64 | 2 | B+ 树层级 | 0，叶子层 |
| 66 | 8 | index ID | `00 00 00 00 00 00 00 f9` → 249 |
| 74 | 10 | 叶子段 FSEG header | 本步不追踪段分配 |
| 84 | 10 | 非叶子段 FSEG header | 本步不追踪段分配 |

为什么有 6 条堆记录却只有 4 行？另外两条是 infimum 和 supremum 系统记录。对于我们无删除、无垃圾记录的范围，`HeapCount = Records + 2`；不要将这个约束不加区别地推广到任意历史表。

`0x8000` 表示新式 compact 记录布局。DYNAMIC 使用这一族页内记录格式；单靠这个位不能判断表是 COMPACT 还是 DYNAMIC，需要表空间标志与可信的表元数据共同约束。

## 5. 先检查第 0 页

读取目标页前，`checkTablespace` 读取第 0 页，检查其类型为 FSP_HDR（8）、FIL/FSP 内的 space ID 与输入一致。偏移 54 的四字节 `FSP_SPACE_FLAGS` 在主案例中为 `00 00 40 21`。

本阶段检查：POST_ANTELOPE、ATOMIC_BLOBS 已设置；ZIP_SSIZE 为 0；PAGE_SSIZE 是默认 16 KiB 编码 0 或显式编码 5；拒绝共享、临时、加密与未知高位。SDI 位可存在，不表示已经解码 SDI。

这帮助及早拒绝已知不兼容输入，但不能替代完整字典校验。无 ALTER/生成列等限制仍由受控样本和输入契约保证。

## 6. 复核一个字段

```sh
python3 - <<'PY'
from pathlib import Path
b = Path('testdata/mysql8045/lesson_rows.ibd').read_bytes()
root = 4 * 16384  # 本样本元数据给出的页号
for offset, size in [(4,4), (24,2), (34,4), (40,2), (54,2), (64,2), (66,8)]:
    raw = b[root+offset:root+offset+size]
    print(offset, raw.hex(' '), int.from_bytes(raw, 'big'))
PY
```

依次得到页号 4、类型 17855、space 40、heap_top 239、记录数 4、层级 0、index 249。

对应代码：`page.go/readPage`、`checkTablespace`、`parseLeaf`。对应测试：真实夹具、显式移动根页、截断文件、页号/ID 不匹配、非叶子页、兄弟页、格式标志和目录边界。

格式依据：[MySQL 8.0.45 page0types.h](https://github.com/mysql/mysql-server/blob/mysql-8.0.45/storage/innobase/include/page0types.h)、[fsp0types.h](https://github.com/mysql/mysql-server/blob/mysql-8.0.45/storage/innobase/include/fsp0types.h)。
