# 07 非叶子记录如何指向子页

学习目标：逐字节解码非叶子导航记录，理解 MIN_REC 与保留 NULL 位图。前置知识：五字节记录头、INT 编码以及第 06 章的树结构。

## 1. 叶子记录和导航记录的区别

当前显式非空 INT 主键范围内：

```text
叶子记录：   变长长度 | NULL 位图 | 5B 头 | INT 主键 | 6B事务ID | 7B回滚指针 | 其他列
非叶子记录：           保留位图 | 5B 头 | INT 键   | 4B 子页号
                                          ↑ origin
```

导航记录 status=1，叶子普通记录 status=0。导航记录不含 score/name 值，也不含 DB_TRX_ID 或 DB_ROLL_PTR；它不是“其他列恰好都为 NULL 的用户行”。

子页号是四字节大端无符号整数，不应用有符号 INT 的最高位翻转。INT 键沿用上一阶段的 `int32(bigEndian XOR 0x80000000)`。

## 2. 一条真实导航记录

`ordered_rows` 根页为 4。第二条导航记录 origin=140，完整区间 `[134,148)`：

| 页内范围 | 文件起点 | 实际字节 | 解码 |
|---|---:|---|---|
| `[134,135)` | 65670 | `00` | 保留 NULL 位图区 |
| `[135,140)` | 65671 | `00 00 19 00 0e` | 普通导航头，heap 3，status 1，next=154 |
| `[140,144)` | 65676 | `7f ff fe eb` | 键 −277 |
| `[144,148)` | 65680 | `00 00 00 06` | 子页号 6 |

头部 `0x0019 >> 3 = 3`，`0x0019 & 7 = 1`。相对偏移 14，使下一条 origin 为 154。下一条键为 178，因此子页 6 对应范围 `[-277,178)`。

运行时除了这条记录，还要确认目标页 6 的 FIL 页号、space ID=47、index ID=256、level=0 均正确。读到“某个有效 INDEX 页”不代表找对了子页。

## 3. 为什么多出一个 NULL 位图字节

主键 id 非空，导航记录也没有可空的 score/name 数据，为什么 `[134,135)` 仍存在？MySQL 8.0.45 的 `rem0rec.cc` 在 NODE_PTR 路径使用索引的 `get_nullable_before_instant_add_drop()` 数量预留位图空间，并初始化为 0。

我们没有 INSTANT 历史，schema 中 score/name 共两个可空列，因此保留 `ceil(2/8)=1` 字节。主键非空，实际导航字段没有 NULL，保留位必须全零。`decodeNode` 计算并检查这一部分，将它计入 `NodePointer.Start`。

深树表所有列都非空，所以没有此保留字节，单条导航记录为 `5+4+4=13` 字节；普通样本是 14 字节。这解释了深树根页首记录 origin=125，而普通样本是 126。

不能凭“内部记录只含主键”就删掉所有前置空间。这里通过真实样本与 [MySQL 8.0.45 rem0rec.cc](https://github.com/mysql/mysql-server/blob/mysql-8.0.45/storage/innobase/rem/rem0rec.cc) 的 NODE_PTR 分支交叉核实；后续支持 INSTANT 时必须重新考虑该计数。

## 4. MIN_REC：字节里的整数不一定是最小键

顺序表根页第一条头为 `10 00 11 00 0e`。第一个字节中的 `0x10` 是 MIN_REC。它与 infimum 不是同一条记录：infimum 的 status 是 2；这条仍是 status=1 的导航记录，只是其下界被视为特殊最小值。

乱序样本的根页首导航记录存储键 **−749**，指向页 5；但页 5 的第一行实际是 **−750**。如果拿 −749 作为整个子树的有限下界，就会误判 −750 或漏读它。

实现规则：

- 每层最左侧非叶子页的第一条导航记录必须带 MIN_REC；其他导航记录不能带该标志。
- MIN_REC 记录使用父任务继承的下界，不使用其存储键作有限边界。
- 其他记录使用各自 INT 键作子树下界；下一条键为排他上界。
- 原始键仍保存在 `NodePointer.Key`，同时公开 `Minimum`，防止调用方误解。

这类特殊下界使以后向树最左端插入更小的值时，不需要把存储键误当作不可突破的界限。

## 5. 三层树中的一跳

`deep_rows` 根页 4 的第二条 origin=138：

```text
固定头 [133,138): 00 00 19 ff e6
INT 键 [138,142): 80 00 10 6b → 4203
子页号 [142,146): 00 00 00 26 → 38
```

`ff e6` 表示向前回到 supremum 的相对编码：`138−26=112`。页面仍使用前几章相同的系统记录与记录链。

到达页 38 后，首条 origin=125 的数据是：

```text
键：  80 00 10 6b → 4203
子页：00 00 02 79 → 633
```

页 38 不是该层最左页，其 Previous=37，所以这条首记录没有 MIN_REC。导航由此从 `4 → 38 → 633` 抵达存放实际行的叶子页。

## 6. 自己复核原始字节

```sh
python3 - <<'PY'
import gzip
from pathlib import Path
b=gzip.decompress(Path('testdata/trees/ordered_rows.ibd.gz').read_bytes())
print(b[65536+134:65536+148].hex(' '))
PY
```

预期：`00 00 00 19 00 0e 7f ff fe eb 00 00 00 06`。

代码对应：`tree.go/decodeNode` 与 `NodePointer`；通用目录/记录链验证位于 `record.go/decodePage`。测试包括保留位图非零、缺少/额外 MIN_REC、子页号越界、错误层级/归属和父子键范围冲突。
