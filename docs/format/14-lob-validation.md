# 14 页外完整值的验证与复现

学习目标：通过独立 SQL 结果确认多页拼接没有截断或重复；理解支持范围与损坏防护；复跑真实样本，沿引用查看任意字段的物理来源。

## 1. 新增夹具及边界

`testdata/lob` 包含三个专用表，来源数据库 `innodb_reader_fixture_f340b8050b59`。生成 SQL、SHOW CREATE、schema、独立 SQL 预期、原始文件 SHA256 均随夹具保存。密码不在文件中。

| 表 | 行数 | 聚簇页数 | 页外字段数 | 数据块数 |
|---|---:|---:|---:|---:|
| lob_sizes | 8 | 1 | 6 | 13 |
| lob_text | 4 | 1 | 2 | 6 |
| lob_mixed_tree | 80 | 5 | 145 | 290 |

三个表共 92 行。最后一个表有根页和四个叶子页，主键为超过 int64 最大值的 BIGINT UNSIGNED，声明在中间；每行混合 VARCHAR、VARBINARY、页内 emoji 标签，部分列为 NULL。共 145 个页外字段验证同一行多个引用、跨聚簇页及不同字段的独立拼接。

之前 `testdata/variable` 的 external_text / external_binary 原始资产不改动，只把第五阶段测试的期望从“拒绝”升级为“完整还原”。其中 manifest 的 expected_error 是第四阶段生成时的历史记录，当前能力以本章和项目 REQUIREMENTS 为准。

因此当前共有 **30 组成功夹具、17544 行 SQL 对照**：此前成功的 17448 行，加原拒绝表的 4 行，再加本阶段 92 行。历史章节保留当时验证状态，不能把当时的拒绝计数当作当前支持范围。

## 2. 容量临界值是怎样验证的

`lob_sizes` 的二进制值按 `00 ff 80` 重复再截取指定长度。既包含 NUL，也包含无效 UTF-8 字节，因此不能用文本方式“看起来差不多”来验收。

| id | 字节数 | 数据块长度 |
|---:|---:|---|
| 0 | 0 | 空值，无页外引用 |
| 1 | 9000 | 9000 |
| 2 | 15680 | 15680 |
| 3 | 15681 | 15680 + 1 |
| 4 | 32007 | 15680 + 16327 |
| 5 | 32008 | 15680 + 16327 + 1 |
| 6 | 60000 | 15680 + 16327 + 16327 + 11666 |
| 7 | NULL | 无页外引用 |

这同时覆盖“首个 LOB 页即可装完”“容量刚好用满”“多出一个字节必须新增数据块”。源码 `ref_t::is_big()` 在 8.0.45 中返回 true，因此本例 9000 字节字段也采用带索引的新格式；不根据字段长度猜测旧 BLOB 页格式。

id=3 的真实记录位于页 4，Start=234、origin=242、End=279；引用在页内 259，字节如下：

```text
00 00 00 4d | 00 00 00 07 | 00 00 00 01 | 00 00 00 00 | 00 00 3d 41
  space77       first7        version1       高位零          15681
```

其两个索引项位于页 7 偏移 96 和 156，分别指向：页 7 偏移 696 的 15680 字节、页 8 偏移 49 的 1 字节。末块不能因为太短而遗漏，也不能错误地读满整个页。

## 3. 文本跨页的独立验证

`lob_text` 包含空字符串、NULL、10000 个 emoji 和 11000 个“界”。40000 字节 emoji 对应页 5/6/7，块长度为 15680、16327、7993；33000 字节中文对应页 8/9/10，块长度为 15680、16327、993。

测试不仅对照最终 SQL 字符串，还检查真实数据块中确实存在单独看不是有效 UTF-8 的片段，以保证测试覆盖了字符跨页场景，而不是巧合地每页都对齐字符。

## 4. 如何避免损坏输入造成错误结果

在分配和读取之前检查：

1. 引用必须恰好 20 字节；表空间匹配，页号非零且非 FIL_NULL，长度为正且不超过列声明最大字节数。
2. 长度还不得超过文件长度；每次读取复用 readPage 的页号与文件边界检查。
3. 首个 LOB 页、后续数据页必须具有相应页类型和版本；仅接受初始未修改 LOB。
4. 首个页内活动项数量为 1..10；槽位地址必须对齐 60 字节，位于 [96,696)，不能重复或循环。
5. 检查前后链、首尾地址、空历史链、初始 LOB 版本及相符的创建/修改元信息。
6. 第一项必须指向首个 LOB 页；数据页不能重复，块长必须匹配页头且符合页面容量。
7. 累计字节数不能超过引用长度，最终必须完全相等；链必须在声明数量后终止。
8. 完整拼接后再验证文本字符数、UTF-8，二进制逐字节保留。

新测试用内存副本构造错误引用空间、页号越界、引用长度为零/过大/不一致、所有权标志、版本、页类型、索引数量、错位槽、循环、重复页、错误前后链接、历史链、块长度和无效文本。所有失败均验证不返回部分表。

未实现的格式返回 ErrUnsupported；可检测的结构损坏返回 ErrCorrupt。任意改变数据字节仍可能形成结构合法的新值；Go 读取路径尚未验证 CRC，schema 仍为可信输入，不声称能识别所有损坏或恢复事务可见性。

## 5. SQL 预期与来源核对

生成器在同一个会话中持有 FOR EXPORT 锁直到 SQL 结果获取及文件复制完成。二进制预期来自 SQL HEX，文本来自 JSON_ARRAY；数字以精确整数形式保留。Go 测试不负责生成自己的预期。

`TestLOBFixtures` 逐列对照 SQL，核对每个引用的原始字节位置，再按返回的 Chunks 直接从文件取原始字节拼接，与列值比较。测试同时断言容量边界对应的块数和字符跨页场景。

`TestLOBDamage` 覆盖引用、页和索引项错误；`FuzzLOB` 在真实页外文本文件上做有界字节改写。旧整数、页内变长字段及深树测试全部继续运行。新增三个文件通过官方 innochecksum。

## 6. 复现

在项目根目录执行：

```sh
go test ./...
go test -race ./...
go vet ./...
GOMAXPROCS=2 go test -run '^$' -fuzz '^FuzzLOB$' -fuzztime=10s -parallel=2
gzip -dc testdata/lob/lob_sizes.ibd.gz > /tmp/lob_sizes.ibd
go run ./examples/read /tmp/lob_sizes.ibd testdata/lob/lob_sizes.json
```

示例输出 8 行 JSON，二进制仍是 Base64，NULL 与空值分开。调用方无需先手动解析页外引用，Read 返回的列值已完整拼接。

如需重新生成，先安全设置 MYSQL_PWD 环境变量，输出目录必须不存在：

```sh
python3 scripts/generate_fixtures.py --lob \
  --mysql /Users/kimihiro/workspace/software/mysql-8.0.45/bin/mysql \
  --socket /Users/kimihiro/workspace/data/mysql/3306/data/mysqld_3306.sock \
  --out /tmp/new-lob-fixtures
```

表空间、事务编号、页分配与哈希可能改变。本手册的数值和字节对应已交付固定资产。

## 7. 接口限制与后续方向

返回结果仍全部驻留内存，外部值长度已用现有列声明约束，但总内存随数据量增加。没有新增流式 API、缓存框架或第三方依赖。

本阶段解决的是现有 VARCHAR/VARBINARY 的页外还原；没有扩展 TEXT/BLOB 类型、压缩与旧 LOB、外部索引页、更新后的历史版本或 undo。后续可先单独规划 TEXT/BLOB 类型与更大的 LOB 索引，继续用逐步可验证的方式扩展。
