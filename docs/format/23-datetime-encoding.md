# 23 DATETIME：五字节主体与小数秒

## 学习目标

本章从文件字节还原年月日、时分秒和小数秒，解释 fsp 为何影响字段长度，以及 DATETIME 为什么不能按 UNIX 时间戳读取。先读第 21 章 DATE 和第 04 章记录定位。

当前支持 MySQL 8.0.45 新建表的 DATETIME2 物理格式；schema 中使用 SQL 名称 DATETIME。旧八字节 DATETIME、TIME、TIMESTAMP 不属于本阶段。

## 声明与输出

```json
{"name":"created_at","type":"DATETIME","fsp":6,"nullable":true}
```

fsp 为 0..6，省略表示零位小数秒，与 DECIMAL 的 precision/scale 分离。DATETIME 不允许 unsigned、max_chars/max_bytes 或非零 precision/scale；其他已支持类型不允许非零 fsp。主键仍限整数。

返回 Go string / JSON 字符串，格式是 `YYYY-MM-DD HH:MM:SS`，fsp>0 时追加恰好 fsp 位小数，包括尾零。例如 `2024-02-29 12:34:56.100`，不能缩成 `.1`。SQL NULL 返回 nil，与零日期时间不同。

支持年 0..9999、月 0..12、日 0..31、小时 0..23、分秒 0..59。沿用 DATE 的物理还原原则，保留零/部分零及 SQL 模式允许存储的非日历日期，不使用 time.Time 归一化，也不猜测时区。

## 物理宽度

| fsp | 主体 | 小数秒字节 | 总宽度 |
|---:|---:|---:|---:|
| 0 | 5 | 0 | 5 |
| 1、2 | 5 | 1 | 6 |
| 3、4 | 5 | 2 | 7 |
| 5、6 | 5 | 3 | 8 |

公式为 `5 + ceil(fsp/2)`。它由声明决定，不随当前值变化。零值占完整宽度，NULL 不占值字节；DATETIME 不消费变长长度项。

官方 [ha_innodb.cc](https://github.com/mysql/mysql-server/blob/mysql-8.0.45/storage/innobase/handler/ha_innodb.cc#L7980) 将 DATETIME2 映射为 DATA_FIXBINARY，因此这些已经打包好的字节不再经过普通 DATA_INT 的倒序/符号转换。

## 五字节主体的编码

主体是大端整数，包含偏置 `0x8000000000`。非负日期时间写入时加上偏置，读取时先减去；小于偏置的编码不属于当前 DATETIME 契约。

忽略偏置后的位布局：

```text
[年月组合：17 位][日：5 位][小时：5 位][分钟：6 位][秒：6 位]
年月组合 = year×13 + month
```

月份与年份先合成一个数，和 DATE 的独立四位月份布局不同。具体公式：

```text
ymd = ((year×13 + month) << 5) | day
hms = (hour << 12) | (minute << 6) | second
主体 = (ymd << 17) | hms
```

反向读取时，年月组合为 `主体 >> 22`，除以 13 得年，模 13 得月；日为 `(主体>>17)&31`，小时为 `(主体>>12)&31`，分钟为 `(主体>>6)&63`，秒为 `主体&63`。

月通过模 13 自然在 0..12，日通过五位自然在 0..31；仍需验证年份和时分秒范围。检查分量不代表检查闰日是否符合日历。

官方依据为 [TIME_to_longlong_datetime_packed](https://github.com/mysql/mysql-server/blob/mysql-8.0.45/mysys/my_time.cc#L1860) 和 [my_datetime_packed_from_binary](https://github.com/mysql/mysql-server/blob/mysql-8.0.45/mysys/my_time.cc#L1950)。本项目逐字段还原，不把打包数解释为距纪元的秒数。

## 真实案例：2024-02-29 12:34:56.123456

夹具 `datetime_fsp_6.ibd.gz` 解压 SHA256 为 `257d6981913464b53b0d99e0580743a1df5c3368b61a142805c5107ed48634c4`。id=12 位于页 4、origin=490；前面仍是四字节 INT 主键和十三字节系统字段，所以 DATETIME 从页内 507 开始，文件绝对偏移为 `4×16384+507=66043`。

```text
99 b2 ba c8 b8 | 01 e2 40
五字节主体      三字节小数秒
```

1. 主体减去偏置：`0x99b2bac8b8 − 0x8000000000 = 0x19b2bac8b8`。
2. 年月组合为 26314，`26314/13=2024`、余数 2。
3. ymd=842077，低五位为 29；hms=51384，拆出 12、34、56。
4. `01 e2 40` 是大端整数 123456，fsp=6 时直接代表微秒。
5. 输出精确字符串 `2024-02-29 12:34:56.123456`。

主体不包含时区名或偏移，解析输出也不追加 Z。不要把这个字符串默认为 UTC 时间点。

## 小数秒为何按两位一组保存

附加字段也是大端。fsp=1/2 时，原值乘 10000 得微秒；fsp=3/4 时乘 100；fsp=5/6 时原值就是微秒。乘回后必须在 0..999999，并且能被 `10^(6−fsp)` 整除。

这项整除检查尤其影响奇数精度：fsp=3 的三位小数 .123 存储为 1230，而非 123；最后一个未使用的十进制位必须为零。读取后不会自行补偿非法低位。

以下是七张 fsp 表中 id=12 的真实附加字节，主体均为 `99b2bac8b8`：

| fsp | 小数秒原始字节 | 整数原值 | 微秒 | 输出尾部 |
|---:|---|---:|---:|---|
| 0 | 无 | 0 | 0 | 无 |
| 1 | `0a` | 10 | 100000 | .1 |
| 2 | `0c` | 12 | 120000 | .12 |
| 3 | `04ce` | 1230 | 123000 | .123 |
| 4 | `04d2` | 1234 | 123400 | .1234 |
| 5 | `01e23a` | 123450 | 123450 | .12345 |
| 6 | `01e240` | 123456 | 123456 | .123456 |

官方 [my_datetime_packed_to_binary](https://github.com/mysql/mysql-server/blob/mysql-8.0.45/mysys/my_time.cc#L1981) 同时给出了存储缩放和小数精度对齐要求。实现使用整数运算，没有浮点转换。

## 零值与边界

零主体是 `80 00 00 00 00`，小数秒字节全零；原始五字节全零不是合法零 DATETIME。fsp=3 的零输出为 `0000-00-00 00:00:00.000`。

全部精度表 id=15 验证 `9999-12-31 23:59:59` 加对应精度最大尾数；fsp=6 的完整字节为 `fef3ff7efb0f423f`。这属于本实例实际成功保存并对照的端点。
