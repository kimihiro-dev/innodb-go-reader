# 25 TIME：负时长与小数秒借位

## 学习目标与契约

TIME 可以表示负值和超过一天的时间间隔。读完本章，你可以解释它的三字节主体，正确恢复负亚秒值，并理解为什么不能分别对主体和小数取绝对值。前置章节为 23 的小数秒和 04 的字段定位。

当前支持 MySQL 8.0.45 新建表的 TIME2 物理格式，schema 使用 SQL 名称 TIME：

```json
{"name":"elapsed","type":"TIME","fsp":6,"nullable":true}
```

fsp=0..6，省略为 0；返回 `[-]HH:MM:SS[.小数]` 字符串，小时至少两位，可达三位，小数严格保留 fsp 位。例：`-25:34:56.100000`。NULL 为 nil，零统一输出不带负号的 `00:00:00` 及对应小数零。

范围为 -838:59:59..838:59:59。端点不能再带非零小数，但 838:59:58.999999 在范围内。小时不按 24 取模；TIME 不接受 unsigned、长度或 DECIMAL 精度属性，也不作主键。fsp 现在同时适用于 DATETIME/TIME，TIMESTAMP 仍未实现。

## 主体与定长宽度

| fsp | 主体字节 | 小数秒字节 | 总宽度 |
|---:|---:|---:|---:|
| 0 | 3 | 0 | 3 |
| 1、2 | 3 | 1 | 4 |
| 3、4 | 3 | 2 | 5 |
| 5、6 | 3 | 3 | 6 |

TIME2 是 DATA_FIXBINARY，不再经过普通整数的 InnoDB 转换。主体三字节按大端读取，减去偏置 0x800000 后得到带符号的打包部分。正值的布局是：

```text
[保留位][小时 10 位][分钟 6 位][秒 6 位]
hms = (hour << 12) | (minute << 6) | second
```

这里是位打包，不是总秒数。例如一分钟的 hms 为 64，不能把它当成六十四秒。校验小时必须使用所有高位，不能掩掉损坏的保留位后继续接受。

DATETIME 的小数秒分组规律仍适用：附加字段一/二/三字节分别乘 10000/100/1 得微秒。但负值必须先恢复借位，不能直接乘。

官方格式与算法见 [my_time.cc:1689–1833](https://github.com/mysql/mysql-server/blob/mysql-8.0.45/mysys/my_time.cc#L1689)；范围检查见 [check_time_range_quick](https://github.com/mysql/mysql-server/blob/mysql-8.0.45/mysys/my_time.cc#L235)。

## 负小数为何需要借位

设三字节主体减偏置为 I，附加 n 字节按无符号大端读取为 F。读取顺序是：

1. 若 I<0 且 F≠0，将 I 加一，并将 F 减去 `2^(8n)`。
2. 此时主体和小数都表示同方向的带符号分量；记录负号后分别取绝对值。
3. 从主体绝对值提取小时、分钟和秒，将小数绝对值缩放为微秒。
4. 校验微秒≤999999，且能被 `10^(6−fsp)` 整除；检查时分秒范围及端点。
5. 格式化完整字符串，再加负号。

对 fsp=5/6，官方源码直接将六字节整体减去 0x800000000000；本实现按三字节主体和三字节小数做上述分解，与整体有符号还原等价。

如果负值的小数是零，不发生补偿。这个分支不能省略，否则整数负秒会被多加一秒。也不能仅把小数取反：当小数存在时，主体同时借了一单位。

## 真实案例一：-00:00:00.01

`time_fsp_2.ibd.gz` 解压 SHA256 为 `0cc5198325334565a803f2f9ee82245ba03c9c596b5b41556e3efa17be9675cd`。id=14 位于页 4、origin=500，TIME 从页内 `500+4+13=517` 开始；文件绝对偏移为 66053。

```text
7f ff ff | ff
主体       小数
```

I=`0x7fffff−0x800000=−1`，F=255。因为两者满足借位条件，补偿后 I=0、F=255−256=−1；小数乘 10000 得 −10000 微秒。主体没有整秒，最终输出 `-00:00:00.01`。

同一夹具 id=4 的原始字节是 `7fffff00`。小数为零，不补偿；主体为 −1，输出 `-00:00:01.00`。只相差最后一个字节，却不是简单地“多了 255 个百分之一秒”。

## 真实案例二：-12:34:56.123456

`time_fsp_6.ibd.gz` 解压 SHA256 为 `ffc15f0c88f8d69f6d172d2a7a48d4503dbaf1f7c3ebc22b4582b014b8c66068`。id=21 在页 4、origin=729，值从页内 746 开始，六字节为：

```text
7f 37 47 | fe 1d c0
```

I=`0x7f3747−0x800000=−0xc8b9`，小数非零，补偿后 I=−0xc8b8，F=`0xfe1dc0−0x1000000=−123456`。主体绝对值 0xc8b8 拆成小时 12、分钟 34、秒 56；小数三字节直接表示微秒，输出负号与六位尾数。

正值对应 `80c8b801e240`。这里的负数不是“把正数最高位清零”，也不是 DECIMAL 的全字节取反规则。

## 极值、零值与实现入口

TIME 零值主体为 `800000`，附加字节全零。SQL 输入负零也会存成这种零，不能从文件恢复一个独立的原始负零文本。

fsp=2 的最大正端点真实编码为 `b46efb00`，还原 838:59:59.00。若同一端点出现非零小数，返回 ErrCorrupt。分钟或秒达到 60、小时达到 839、保留位导致小时越界、奇数精度小数低位未补零也必须拒绝。

`time.go/timeWidth/decodeTime` 以整数运算完成解码；`record.go` 在 NULL 判断后按固定宽度读取。没有变长长度项，不需要 time.Time 或浮点数。下一章解释混合记录、SQL 舍入和验证方法。
