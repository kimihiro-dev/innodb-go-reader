# 53. 从变长聚簇键还原完整记录

<a id="53从变长聚簇键还原完整记录"></a>

本章学习如何把已经能解码的列类型放入主键，并正确找到事务字段、普通列和非叶子的子页号。前置知识是第 11 章的逆向长度数组、第 51 章的复合键物理顺序。比较与树范围见[第 54 章](54-key-order-validation.md)。

<a id="1-值解码和索引比较是两件事"></a>

## 值解码和索引比较是两件事

VARCHAR 能转成字符串，不意味着已经能比较索引键。主键还要求知道字符排序规则、每个成员的方向以及完整物理宽度。本阶段支持以下完整、非 NULL 主键成员；总成员数 1..16，声明最大字节总数不超过 3072。

| 成员 | 物理载荷 | 公开返回值 |
|---|---|---|
| 五类整数，含 UNSIGNED | 原有大端整数编码 | 各自宽度整数 |
| BINARY / VARBINARY | 原始字节，分别定长/变长 | 独立 `[]byte` |
| CHAR / VARCHAR | 指定字符集字节 | UTF-8 `string`，CHAR 去尾 U+0020 |
| DECIMAL | 原有定长 packed decimal | 保留 scale 的精确字符串 |
| BIT | 原有定长大端位字段 | `uint64` |
| DATE / YEAR | 原有定长日期/年份编码 | 日期字符串 / `uint16` |
| DATETIME / TIME / TIMESTAMP | 原有当前格式及 fsp=0..6 | 原类型的精确字符串 |

字符键只允许 utf8mb4_bin、utf8mb3_bin、ascii_bin、latin1_bin；与普通字符列的解码支持范围不同。FLOAT/DOUBLE、ENUM/SET、TEXT/BLOB 前缀、JSON、空间键尚不支持。键的声明宽度不能为零，但 VARBINARY/VARCHAR 的实际值可以为空。

`Column.Collation` 对字符键必须显式填写，且必须匹配 Charset；默认 Charset 是 utf8mb4。`Descending:true` 表示该成员 DESC，省略表示 ASC。两个属性仅用于键。单列 `primary_key` 和多列 `primary_keys` 保持互斥，数组顺序就是索引声明顺序。

自动发现从 DD 元素的 order=2/3 得到 ASC/DESC，从 collation ID 46/83/65/47 得到四个规则；同时检查元素长度等于完整键的声明宽度，拒绝前缀。普通字符列不新增 collation 属性，保持原 schema 行为。

<a id="2-长度数组也跟着物理列序走"></a>

## 长度数组也跟着物理列序走

示意布局（从低地址向高地址）：

```text
逆序存放的变长长度 | NULL 位图 | 5 字节记录头 | ← origin
主键成员 1 | 主键成员 2 | … | 6 字节 TRX_ID | 7 字节 ROLL_PTR
非键列，保持 SQL 声明顺序
```

旧阶段主键都是定长整数，所以所有变长列恰好仍按 SQL 声明顺序出现。现在必须先遍历键列，再遍历剩余列，逐项向低地址消费长度。否则当普通 VARCHAR 在 SQL 声明中位于主键之前时，就会把它的长度当成主键长度。可空列仍只在非键部分，位图按该部分的物理顺序读。

声明最大宽度决定一/两字节长度的规则，实际长度决定载荷占用。例如 VARBINARY(768) 的实际 127 字节用一字节长度，128 字节用两字节；最大宽度不能直接当作字段实际长度。外部标志对主键明确拒绝，普通列继续走既有 LOB 路径。

代码对应 [record.go](../../record.go) 的 `decodeRecord`，用 `physical` 保存键在前的列序；`fixedWidth` 复用现有类型宽度，`decodeKeyValue` 复用各类型解码器。每个键解码通过后保存独立的原始字节用于比较，非法文本/小数/日期编码不能绕过原类型校验。

<a id="3-真实例子先声明-doc先存储-text"></a>

## 真实例子：先声明 doc，先存储 text

交付的 `testdata/keys/keys_lesson` 列顺序为：

```sql
doc MEDIUMTEXT NULL,
tie INT NOT NULL,
k VARBINARY(768) NOT NULL,
text VARCHAR(32) COLLATE utf8mb4_bin NOT NULL,
PRIMARY KEY (text DESC, k ASC, tie DESC)
```

下面是 `text='a', k=128 个 0x61, tie=1, doc=20000 个“中”` 的真实记录。页号 4，页内 `Start=120, Offset=131, End=297`。页大小 16384，因此 origin 的文件绝对偏移是 `4×16384+131=65667`。以下表格都是**页内偏移**，结束位置不包含在区间内。

| 页内区间 | 字节 | 解释 |
|---|---|---|
| 120..126 | `14 c0 80 80 01 00` | 长度数组和 NULL 位图 |
| 126..131 | `00 00 10 ff ed` | 5 字节头；heap number=2，普通记录 |
| 131..132 | `61` | 第一个键 text，一字节 a |
| 132..260 | `61` 重复 128 次 | 第二个键 k |
| 260..264 | `80 00 00 01` | 第三个键 tie，有符号 INT 1 |
| 264..270 | `00 00 00 00 86 95` | TRX_ID 原始 6 字节 |
| 270..277 | `82 00 00 01 35 01 10` | ROLL_PTR 原始 7 字节 |
| 277..297 | `00000231 00000005 00000001 000000000000ea60` | doc 的 20 字节页外引用 |

逆向读元数据的步骤：

1. 125 的 `00` 是 NULL 位图，doc 非 NULL。
2. 124 的 `01` 是 text 实际一字节。
3. 123 的 `80` 与 122 的 `80` 合成 k 的长度：`(0x80 & 0x3f) << 8 | 0x80 = 128`。
4. tie 定长，不消费长度。
5. 121 的 `c0` 与 120 的 `14` 表示 doc 本地长度 20，并置外部位；引用的长度 `0xea60=60000` 是完整文本字节数。

这里叶子 `End` 只包含本地引用；实际 doc 仍完整还原为 20000 个字符。VARCHAR 的 a 与 VARBINARY 中的 a 虽然字节相同，比较规则却不同。

同页另一行 `text='a ', k='', tie=2, doc=NULL` 的 `Start=297, Offset=305, End=324`，元数据为 `00 02 01`：逆向先读 NULL=1，再读 text=2，k=0；doc 为 NULL 不消费长度，也无载荷。空二进制返回非 nil 的空 `[]byte`。

SQL 返回顺序为 `('中', ff×256,3)`、`('a ',空,2)`、`('a',61×128,1)`：第一个成员 DESC，后两行的 text 按 PAD SPACE 相等，继续由第二个成员的二进制升序决定。

<a id="4-非叶子键长度之后才是子页号"></a>

## 非叶子：键长度之后才是子页号

非叶子不存 TRX_ID/ROLL_PTR，不存普通列的载荷或长度；它保留索引的 NULL 位图空间，但所有键非 NULL，所以位图必须全零。

```text
键的逆序长度 | 保留 NULL 位图 | 5 字节头 | 完整键成员 | 4 字节子页号
```

`keys_deep` 有 3000 行，根页 4 的 level=2；读取 494 个聚簇页、493 条导航记录。真实根页一条有限导航记录为：

| 页内偏移 | 字节/值 | 意义 |
|---|---|---|
| 4185..4188 | `00 04 00` | binary 长度 0、k 长度 4、保留位图 0 |
| 4188..4193 | `00 00 61 f8 7d` | 普通非叶子头，status=1 |
| 4193..4197 | `30 30 35 36` | k="0056" |
| 4197..4201 | `80 00 0b 10` | tie=2832；中间 binary 长度为零 |
| 4201..4205 | `00 00 00 2f` | 子页号 47 |

这条记录的 `NodePointer.Key` 是 `["0056", []byte{}, int32(2832)]`。文件绝对 origin 为 69729，子页号仍是大端 uint32。子页字段位置必须由**实际**键长度累计得出，不能按最大声明宽度或 SQL 列顺序猜测。

入口是 [tree.go](../../tree.go) 的 `decodeNode`。CHAR 导航键的公开值同样去尾空格，但树比较仍使用未裁剪原字节；二进制导航键保留独立切片。下一章说明为什么这两种表示必须分开。

<a id="5-源码与边界"></a>

## 源码与边界

上述字节均来自本阶段最终交付快照，SQL、SHA256 和完整 SDI 随夹具保存。源码以用户提供的 MySQL 8.0.45 为准：`storage/innobase/handler/ha_innodb.cc:7957–7994` 映射 BIT/NEWDECIMAL/日期时间到 InnoDB 基础类型，`storage/innobase/dict/dict0dict.cc:3683–3707` 构造完整唯一键加子页号；COMPACT 长度规则沿用 `storage/innobase/rem/rem0rec.cc` 的记录编码路径。

本阶段仍只支持既定 DYNAMIC、16 KiB、未加密/未压缩、只插入快照，不扩展 UPDATE/DELETE、MVCC、隐藏聚簇键或二级索引。主键完整读取和正确排序只是树解析条件，并不等于事务恢复。
