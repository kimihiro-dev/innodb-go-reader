# InnoDB Go Reader v0.1.0

首个带版本标签的源码版本，提供离线InnoDB文件读取与七命令CLI，并附中文使用指南、01–84章物理格式解析手册及固定测试资产。

源码标签：[`v0.1.0`](https://github.com/kimihiro-dev/innodb-go-reader/tree/v0.1.0)。固定提交：[`116de5046aa94b379ce4d2e0711e34be9766c397`](https://github.com/kimihiro-dev/innodb-go-reader/commit/116de5046aa94b379ce4d2e0711e34be9766c397)。

## 主要功能

- `metadata`：自动发现表身份、列定义、索引入口、可用schema与不支持原因。
- `export`：流式导出当前行，支持带类型无损JSONL/CSV、可选物理来源、显式仅物化视图及原子文件输出。
- `query`：聚簇键点查、开闭/无界范围、完整前导列等值、逆序和Limit；二级索引支持覆盖投影、前缀候选复核与按需回表。
- `check`：分别验证完整聚簇行、选定二级树或空间分配范围。
- `space` / `page`：严格分析空间分配与已支持页结构，查看段、区、索引及页内布局指标。
- `visualize`：生成自包含离线HTML，支持选定索引树、页/记录/LOB来源及原始字节钻取。
- 完整普通分区文件集合支持元数据、逐分区导出和行检查，并保留分区来源。

列值覆盖整数与UNSIGNED、精确DECIMAL、FLOAT/DOUBLE、日期时间、BIT、CHAR/VARCHAR、二进制与TEXT/BLOB、ENUM/SET、二进制JSON、二维GEOMETRY家族和SQL NULL。支持复合键及ASC/DESC、无显式主键布局、受控更新/删除快照、当前LOB值、原生INSTANT ADD/DROP和STORED/INVISIBLE物化列。

## 输入与使用边界

- 已验证输入为MySQL **8.0.45**、**16 KiB**、独立非压缩非加密表空间、**DYNAMIC/COMPACT**，文件必须是目标写事务结束后的稳定快照。
- 完整类型物化的单值上限为 **16 MiB**；VIRTUAL需要显式 `--materialized`，不计算生成表达式。字符索引键仅支持已验收的四个 `_bin` 排序规则。
- 不承诺其他MySQL/MariaDB版本、页大小、系统/通用表空间或压缩/加密支持；不实现MVCC历史恢复、redo/undo回放或在线采集。
- 不支持子分区、集合查询或跨分区全局键归并，也不解析FULLTEXT/SPATIAL/函数/多值索引。
- CSV使用带类型单元格协议；JSONL须核对完成标记，CSV完整性依赖生产命令退出状态或原子文件输出。局部查询和空间成功不等于整表或事务一致性认证。
- v0.1.0是本次源码与资产标识，不增加永久API兼容承诺；当前CLI没有 `--version` 参数。

## 使用示例

macOS/Linux解压后执行；Windows将程序名换为 `innodb-reader.exe`：

```sh
./innodb-reader --help
./innodb-reader metadata table.ibd
./innodb-reader export --format jsonl --output rows.jsonl table.ibd
./innodb-reader check --scope rows table.ibd
./innodb-reader visualize --index PRIMARY --pages 0,4 --output detail.html table.ibd
```

页号和索引名需按实际文件调整，输出文件默认不能已存在。产品无需Go、Python、Node或运行中的MySQL服务；从源码编译需要Go 1.25或更高版本。

## 二进制资产与验证

多平台构建命令生成以下资产，创建Release时一并上传：

- `innodb-reader_v0.1.0_darwin_amd64.tar.gz`
- `innodb-reader_v0.1.0_darwin_arm64.tar.gz`
- `innodb-reader_v0.1.0_linux_amd64.tar.gz`
- `innodb-reader_v0.1.0_linux_arm64.tar.gz`
- `innodb-reader_v0.1.0_windows_amd64.zip`
- `innodb-reader_v0.1.0_windows_arm64.zip`
- `SHA256SUMS`

构建采用 `CGO_ENABLED=0` 和 `-trimpath`。六个平台均通过交叉编译；本轮仅在macOS ARM64执行固定样本烟测，其他目标未作运行验收。下载文件后，在同一目录使用 `shasum -a 256 -c SHA256SUMS` 核对完整性。

Windows PowerShell使用 `Get-FileHash .\innodb-reader_v0.1.0_windows_amd64.zip -Algorithm SHA256`，与SHA256SUMS中的对应值比较；ARM64包替换文件名。

源码沿用首版已保存的SQL/官方工具对照、race/vet/fuzz及失败保护证据。本轮未修改解析实现或原始夹具，也未重新执行全部长回归；具体证据及当前支持矩阵见下方文档。
